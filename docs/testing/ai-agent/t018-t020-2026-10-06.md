## 改动要点

`TurnRunner` 不再直接调用工具，每次工具调用走：

1. `ToolCatalog::describe` —— 未知工具 → 受控 `unknown_tool`；
2. `ToolCatalog::prepare` —— JSON Schema 校验（`additionalProperties` / `required` / `maximum` 真正生效），失败 → `invalid_arguments`，不执行；
3. `audit_or_fail_closed` —— 强制 `SecurityAuditHook`，返回 `Err` 或 `Deny` 一律拒绝；
4. `authorize` —— Agent 白名单 ∩ 连接内核权限 ∩ 风险 ∩ 审计，**deny 优先**；
5. `Allow` 才取 `executable` 执行；`RequireApproval` 时**不执行**，发 `LoopEvent::ApprovalRequired { plan_hash, scope }` 并 `TurnOutcome::Paused`；
6. `ToolCatalog::project` —— 回给模型的是有界投影，原始 `ToolReceipt` 不被改写。

其它：

- 删除 `ai_loop.rs` 中与 `ToolCatalog` 重复的简易 `ToolRegistry`。
- `TurnState.target_json`（T021 固定目标）参与 `plan_hash`：目标变化 → 旧审批/审计自然失效。
- `TurnPermissionContext { agent_allowed_tools, policy, plugin_digest }`。
- 拒绝不是文案：合成 `ToolReceiptStatus::Denied` 回执回给模型，工具真实调用次数为 0。
- `ai_sql_exec.rs` 新增 `AiSqlExecuteTool`（`db.execute`，Write）与 `standard_sql_catalog()`：
  默认不装写工具（`db.execute` 的 spec 也一并移除），显式 `include_write=true` 才装，避免“spec 可见但不可执行”。

## 子 Agent A 独立测试（`tests/ai_loop_authz.rs`，8 用例全过）

全部走 `TurnRunner` 生产链路，并用 `RecordingTool::call_count()` 断言真实副作用次数：

| # | 场景 | 预期 | 结果 |
|---|---|---|---|
| 1 | Write 工具 + `KernelPolicy::default()`（不可写） | Denied 回执、`call_count()==0` | 通过 |

| 6 | Read 工具 + 审计 `RequireApproval` | Paused + 审批、不执行 | 通过 |
| 7 | `plan_hash` / `approval_matches` 表驱动 | 参数/target/版本/digest 变即失效 | 通过 |

## 未完成 / 已知缺口

- **运行时 actor 未接**：`ai_runtime.rs` 的 `AiEvent` 只有流式文本/工具请求/结束，没有工具执行、审批、回执事件；`TurnRunner` 目前只被测试驱动，UI 还跑不到这条链路。这是下一步（T016/T018 集成 + T028 面板）。
- **审批行持久化未做**：`ai_approvals` 的写入、决定回填、按 `plan_hash` 复核、append-only 审计表落盘都还没有；当前审计/审批只存在于内存。
- **UI 审批卡未做**：T020 的“询问 AI 抽屉内联批准卡”属于下一阶段。
- **插件层未接**：`authorize` 目前由内核直接调用，插件 Allow/Deny 尚未接入，故“插件不能覆盖内核 Deny”只在内核层成立。
- **真实模型/真实库未验证**：本轮全部为 scripted Provider + RecordingTool，未调用真实模型，也未连真实数据库。
