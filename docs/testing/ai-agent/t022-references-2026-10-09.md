# T022 `@` 引用、候选检索与附件 UI 实施与验收（2026-10-09）

平台：macOS arm64（真实窗口未执行，见「未验证」）。全部自动化使用隔离临时目录与本地 Mock，不读生产凭据、不联网、无付费请求。

## 交付（按本轮缺口 1–8 修复）
1. 候选类型补齐：`ai_reference_candidates` 除连接/库/schema/表/视图/列/索引/集合/Redis DB/Redis Key/知识外，新增保存查询、编辑器选区、结果页快照；已授权附件进入 `@` 检索。保存查询走 `storage.load_saved_queries()`（`ai_storage()`），同名靠连接/库/schema 与稳定 ID 区分。
2. 无匹配与检索失败分离：`ai_reference_candidates` 返回 `Result`，`ai_reference_errors` 汇总逐项失败；UI `reference_error` 显示「检索失败：…」，与「无匹配引用」互斥；新增 `ai-reference-search-error` 证据节点。
3. 失效引用可见：chip 前先跑 `ai_reference_errors`（后台、随会话加载刷新），失效项红色边框 + 「失效」标记 + tooltip 说明（`ai-reference-invalid:<id>`）；跨连接/库/schema 合并冲突也提前标记。发送仍走完整定位与合并校验。
4. 详情按需读取：新增 `context.read` 工具（`ai_reference_details.rs`）读取保存查询/选区/结果页快照，`ctx.session_id`/`turn_id` 必须匹配本轮，参数 `reference_id/offset/max_bytes` 受 schema 校验；结果页为有界快照（列 32、行 10、单元格 128 字符，二进制只记字节数，`has_more` 标记截断），不再编造 `table-page:…` 假句柄。
5. `@ 不给写权限`：system 提示明确「引用只提供上下文与只读定位，不授予写权限，写操作仍走审批」；`explicit_reference_never_grants_write_or_bypasses_approval` 断言只读连接 Deny、可写连接 `waiting_approval`，两者真实工具调用次数均为 0，且未批准不执行。
6. 检索与授权异步化：`refresh_ai_reference_menu` 后台执行并带 `reference_epoch`/会话 epoch 丢弃迟到结果；加载态可见且 Enter/方向键在加载中不误确认；附件选择带 `attachment_loading`，并发选择被拒、会话切换后丢弃并提示，发送/`@` 期间禁用，空结果不伪造候选。
7. 交互收口：候选浮层内点击阻止穿透，外部点击先关浮层并 `stop_propagation`（不激活下层按钮）；Esc 关浮层不关面板；`@` 触发按词边界识别，避开邮箱/`@` 前缀误触发。
8. 会话标题生成与新引用上下文兼容：`generate_session_title` 首轮成功后会额外发一次独立标题请求，修正相关测试期望（`ai_session_model_selection`、`ai_restart_recovery` 的 `provider.call_count`）。

文档/数据面：运行快照新增 `reference_grants`（仅存 ID/kind/有界正文/截断位，宿主侧校验后再入库）；公开 `context_references` 仍只含 ID/标签/kind/summary/target，正文不进公开上下文。`TurnState` 增加 `session_id`/`turn_id` 并透传到 `ToolExecutionContext`，工具执行身份可核对。

## 真实窗口端到端（引用 → 模型 → 工具 → 回执 → 结果，本轮已做）
用**本地 mock OpenAI Chat Completions 模型**（`docs/testing/ai-agent/t022_mock_model.py`，127.0.0.1:39107，不联网、无凭据）+ 扩展后的离线夹具（`cargo run -p fluxdb-app --example ai_reference_fixture -- /private/tmp/fluxdb-t022-e2e`，模型端点指向本地 mock），在**真实可见窗口**（900x700）执行：点击输入框 → 键入 `@订单` → 方向键 + 回车选中「保存查询：订单口径」→ 输入提示 → `cmd+enter` 发送。

生产链路真实跑通（非脚本化流式夹具）：`submit_conversation` → 读取真实 `runtime_snapshot` → `context.read` 工具经真实内核授权/执行 → 真实回执写入下一轮 → 最终助手正文。

数据库与请求侧证据：
- mock 收到 **3 次**请求：第 1 次主生成、第 2 次带工具回执继续、第 3 次会话标题。`ai_turns.status = completed`。
- 第 1 次请求（`mock-model.log`）只含引用**元数据**（`id/label/kind/summary/target`），**不含**保存查询正文——证明「只传显式引用/摘要」。
- 第 2 次请求携带 `[tool]` 回执：`{"tool":"context.read","status":"succeeded","result":{"reference_id":"saved_query:…","kind":"saved_query","text":"SELECT status FROM orders WHERE id=2;","has_more":false,"untrusted":true,"scope":"用户已选择的有界快照…"}}`——正文经 `context.read` 按需到达。
- `ai_tool_calls`：`context.read / succeeded`；助手正文含该回执片段。
- 界面：chip「订单口径」→ 用户气泡 → 工具卡「已完成 1 项操作」→ 最终回复正文。

证据：`/private/tmp/fluxdb-t022-shots/e2e-chip.png`（选中 chip）、`e2e-prompt.png`（引用 + 提示）、`e2e-result.png`（工具卡与最终回复）、`e2e-mock-model.log`（3 次请求 + 工具回执原文）。

覆盖与边界：本 E2E 证明了「`@` 选择 → 引用只读上下文 → 工具按需读取 → 真实回执进入下一轮 → 结果可见」这一 T022 核心闭环；写权限边界（引用不授予写、写必审批）由 App 集成用例 `explicit_reference_never_grants_write_or_bypasses_approval` 证明。mock 模型不是真实第三方模型，原生系统对话框/IME/无障碍仍属系统级未测项。
