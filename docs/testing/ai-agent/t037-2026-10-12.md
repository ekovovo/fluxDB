# T037 Jev 自动装配与故障策略（2026-10-12，macOS arm64）

## 结论

**已勾选**（2026-10-12）。受控故障测试与真机实测均通过；deadline 与重试策略按真机
实测调整过一次（3000ms → 8000ms，并新增按错误类别的有限重试）。

## 一、交付内容

### 自动装配（`crates/fluxdb-app/src/parts/ai_jev.rs`，设计 §18.1）

- `reconcile_jev_builtins`：默认决策模型优先 → 唯一合格候选自动使用 → 多候选无默认
  转「待选择」。写入 `ai_agent_model_bindings`（`role=decision`、`binding_source=system`）；
  **`user` 绑定不被覆盖、不被停用、不产生重复行**。已存在用户绑定时不再挂 system 候选。
- 触发点：启动（`ai_recovery.rs`）、模型保存/启停、凭据 Set/Clear、默认决策模型变更、
  Agent 新建/编辑、插件启停、全局出站闸门。
- 协议资格只看 `api_protocol == "system-one"`，**不按模型名猜协议**（名字含 `jev` 但协议
  不符的模型判为「暂不可用」且不建立绑定）。

### 状态（`JevStatus` / `JevStatusKind`）

未配置 / 已禁用 / 可用 / 待选择模型 / 暂不可用（附脱敏原因 + 熔断截止）。
UI（`#plugins`、`#models`）与运行期**共用同一判定**，不存在两套口径。

### 故障策略

- 连续 3 次失败熔断 60s，成功或窗口过期即清零；**每次失败都计入熔断，重试不绕过熔断**。
- Jev 只做引用排序建议，**绝不参与 SQL/文件权限裁判**；调用失败不阻断基础 Agent。

## 二、deadline 与重试的修订（真机实测驱动）

真机实测 `inception/mercury-decide:free`（OpenRouter `/api/alpha/decisions`）单次决策
在 **2.4s–7.2s** 波动，3000ms deadline 会砍掉一半以上真实请求：

| 时刻 | outcome | usage | 说明 |
|---|---|---|---|
| 11:08:14 | `error` 请求超时 | `unknown` | 3000ms deadline，超时 |
| 11:46:39 | `adopted` | `actual` 238/1 | **8000ms + 重试生效** |
| 11:47:50 | `adopted` | `actual` 242/1 | 成功 |
| 12:25:29 | `rejected` 候选概率无明显优势 | `actual` 244/1 | 低置信度主动放弃 |

因此 `DECISION_DEADLINE_MS` 由 3000ms 上调为 **8000ms**，并按 Pi 复刻的
OpenAI/Anthropic SDK 策略新增**按错误类别的有限重试**（设计 §18 原写「无自动重试」，
本次按实测修订）：

| 错误类别 | 重试 | 理由 |
|---|---|---|
| 网络层失败、408/429、5xx | 1 次 | 瞬时故障 |
| 401/403、协议不合法、缺凭据、端点无效、取消 | 0 次 | 确定性失败，重试只是把已注定的等待再乘一遍 |

退避 `0.2s→0.4s` 带 ±25% 抖动、50ms 分片以便响应取消。为让重试层能识别错误类别，
`fluxdb_core::Error` 新增 `http_status: Option<u16>` 与 `is_retryable()`。

**单轮最坏 16.4s**（8s × 2 + 0.4s），熔断 3 轮约 49s。熔断是「不每轮等待」的实际保证，
不是压缩 deadline。

- `--test ai_jev_failure_policy` **8 passed**：无凭据零传输、非法返回、低置信度、

### 真机（隔离实例 `FLUXDB_PROFILE=t037`，用户本机真实决策模型）

主模型 `vllm/DeepSeek-V4-Flash`（Provider 须为 `openai`；配成 `anthropic` 会因协议错配
报「网络错误: Other」，与 Jev 无关）。全部结论由 `ai_run_events` / `ai_usage_ledger`
独立核对，非只看提示文字。

| 验收项 | 结果 | 证据 |
|---|---|---|
| 仅保存启用合格模型即自动可用 | 通过 | 无需安装/手工建实例或绑定，system 绑定自动建立 |
| 真实 decision 调用 | 通过 | `decision_advice` + `purpose=decision` `actual 244/1` |
| 超时回基础路径 | 通过 | 3000ms 下 `error 请求超时`，任务仍 `completed` |
| 关闭 Jev → 零调用 | 通过 | 关闭后 3 引用消息任务 `completed`，事件数与用量**均不增长** |
| 低置信度降级 | 通过 | `rejected 候选概率无明显优势`，引用保持原序，任务照常完成 |
| 连续失败熔断 | 通过 | 第 3 次失败后下一轮零请求（事件数不增、耗时 4s 而非 7s） |
| 多候选无默认不擅自选 | 通过 | 「待选择模型」，**无启用绑定**，事件数不变 |
| 唯一候选自动恢复 | 通过 | 删除第二候选后状态回「可用」，system 绑定指向唯一模型 |

## 四、遗留观察（未改，属产品决策）

熔断窗口 60s 相对单次失败成本（8s × 2 + 退避 ≈ 16.4s）偏短：失败计数容易在攒满
阈值前跨过窗口边界，导致需要多轮才能观察到熔断。功能正确，仅参数偏保守。若希望更快
触发，可考虑阈值 3→2 或窗口 60s→120s；本次按设计 §18 原值保留。
