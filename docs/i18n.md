# 界面国际化

本文说明 FluxDB 的语言包格式、加载顺序和新增语言流程。新增语言不需要修改
Rust 代码、语言枚举或构建脚本。

## 目录与加载顺序

语言包按 locale 分目录：

```text
locales/
  en/
    manifest.json
    app.json
  zh-CN/
    manifest.json
    app.json
```

加载来源依次为：

1. 安装包内的 `assets/locales`。
2. 当前 profile 数据目录下的 `locales`。

用户语言包与内置语言包使用相同 locale 时按条目覆盖；格式错误或被拒绝的覆盖项
不会删除已经可用的内置翻译。新增语言只加载用户包中的条目，缺失条目回退英文。

各平台 profile 目录遵循既有存储规则：

- macOS：`~/Library/Application Support/fluxdb`（设置 `FLUXDB_PROFILE` 时带后缀）。
- Windows：`%LOCALAPPDATA%\FluxDB`。
- Linux：`$XDG_DATA_HOME/fluxdb`，缺省 `~/.local/share/fluxdb`。

## `manifest.json`

```json
{
  "format_version": 1,
  "locale": "ja",
  "native_name": "日本語",
  "english_name": "Japanese"
}
```

约束：

- 目录名必须与 `manifest.json` 的 `locale` 一致。
- `locale` 使用 BCP 47 风格的 ASCII 子集，例如 `fr`、`pt-BR`、`zh-CN`。
- `native_name` 用于语言选择器，为空会导致整个包被拒绝。
- 当前只支持 `format_version: 1`。

## 翻译文件

除 `manifest.json` 外，每个 JSON 文件名是一个命名空间：

- `app.json` 生成 `app.*` key。
- `gpui_component.json` 生成 `gpui_component.*` key，用于覆盖 GPUI Component 的
  内置文案。

文件可以嵌套，加载时转换为点分 key：

```json
{
  "settings": {
    "appearance": {
      "language": "言語"
    }
  }
}
```

上例提供 key `app.settings.appearance.language`。

要求：

- JSON 叶子必须是字符串，不能是数组、布尔值或数字。
- 同一语言包内不能出现重复的展开 key。
- 变量使用 `%{name}`，同一条目的占位符集合必须与现有翻译一致。
- 单文件上限 1 MiB，单包最多 32 个 JSON 文件；不允许通过符号链接加载文件。

## 新增语言

1. 复制一个现有语言目录，例如 `en`。
2. 修改 `manifest.json` 的 locale 和 native name。
3. 翻译 `app.json`；需要覆盖组件文案时增加 `gpui_component.json`。
4. 将目录放入安装包的 `assets/locales`，或当前 profile 的 `locales`。
5. 重启应用。设置 → 外观 → 语言会自动列出新语言。

用户目录中的语言包不要求包含全部 key。缺失 key 回退英文，因此可以先发布部分
翻译。应用运行期间新增的目录需要重启后才会被发现。

数据表底栏（新增/删除/提交/取消/刷新/停止）、待提交 SQL 预览与复制、查找数据、

布局切换，以及快捷键说明已迁移；快捷键定义中的英文 title/detail 仅作未命中
映射时的兜底。

终端会话状态/危险命令提示、编辑器补全文档/查找替换栏、数据表操作列与字段
类型校验提示已迁移。SSH 认证方式与云提供方下拉改用稳定值与译文标题，避免
按展示文案回灌表单。

JSON 编辑器（格式错误定位、空态、格式化/编辑/保存）以及备份模式、危险表操作
标题/提示、外键检查下拉已迁移。外键检查下拉同样改用稳定值，不再按中文标签回填。

单实例启动提示、连接树默认分组名/表头、备份恢复摘要已迁移。剩余中文主要是
`tracing`/启动诊断日志、应用层稳定值/中文兜底和测试夹具，
以及应用层返回的
部分校验/错误消息。不能仅按中文字符串计数判断完成度：
日志、注释、SQL/协议值、模型输入输出和原始错误需要分别判定。
迁移时应逐区域补齐 `en`/`zh-CN` 并运行字面量 key 扫描。

数据库返回的原始错误、对象名、SQL、Redis 命令、用户数据和 AI 已生成内容不随
界面语言改写。复数、日期、数字和货币格式化也不由 `rust-i18n` 自动处理。

迁移完成度以“还有没有用户可见中文”判断，而不是把字面量清零：剩余命中已逐项
核对，集中在内核/应用层稳定值、协议列名、日志与测试夹具。新增语言仍只需放入
JSON 语言包；词条缺失回退英文。

## 应用层错误消息

`fluxdb-app` / `fluxdb-core` 不依赖 UI 语言包。桌面端在展示边界通过
`localize_backend_error_text` 翻译已知中文错误，未命中的消息原样保留。覆盖范围
包括：

- 静态错误消息：`fluxdb-app` / `fluxdb-core` 中全部 `Error::new` 直接消息
  （连接、标签页、数据编辑、附件、AI 任务、SQL 作用域、备份恢复、Redis 校验、
  模型与工具注册等）。
- 连接器与存储层的高频用户可见错误：连接超时/类型不匹配、Redis 操作与回包异常、
  配置/Agent/模型冲突、MCP 状态等。
- 动态错误模板：带参数的 `format!` 消息，通过稳定前后缀和占位符替换翻译；
  参数值（SQL、对象名、数据库原始错误等）保持原样。
- 通用模板匹配：`backend_errors_templates.rs` 按字面片段和占位符顺序匹配
  `format!` 结果，具体模板优先于通用模板，参数值原样回填。
- 应用层校验/状态消息：创建表、连接表单、AI 页读取、决策协议、附件路径等
  通过 `String` / `UserError` 返回的消息，以及 `UserError` 标题。
- 内置 AI 插件声明：插件名称、摘要、配置分组、字段标签/说明/占位符、Jev 状态
  详情与插件配置校验错误。

展示接入点包括 `show_message`、页面级错误块、用户/权限错误行和 AI 聊天错误提示。
语言包测试会校验 `en`/`zh-CN` 的 key 与 `%{...}` 占位符一致，并检查动态 key
表引用的词条确实存在。

这仍是展示边界过渡方案：新增后端错误或修改中文措辞时，需要同步更新映射表和
语言包。长期应把用户可见错误改为稳定错误码 + 参数，由桌面端按 code 翻译，
从而彻底移除按中文文本匹配；数据库返回的原始错误不会由本层改写。当前四个后端
crate 的静态错误与普通字符串错误已全部进入映射；剩余未翻译的 `format!` 主要是
AI system prompt、页面上下文和报告正文模板，按下方“不随界面语言改写的内容”保留。

## 不随界面语言改写的内容

以下内容按语义固定，翻译它们会改变程序行为或模型输入，因此保留原文：

- **AI 上下文与提示词**：`ai/current_page.rs` 的页面标签、`details` 与 `notes`、
  system prompt 和工具声明。这些会经 `CurrentPageContext::public_json` 或工具目录
  进入模型消息，按语言改写会让同一个页面在不同语言下产生不同请求。建议按钮写入
  输入框的 prompt 已改用语言包。
- **AI 产物与模型输出**：报告正文、模型生成的解释与总结不翻译。
- **内核审计事实**：`ai/approval.rs` 的 guardrail 文案来自内核策略层
  （`fluxdb-core` / `fluxdb-app`）。图标档位仍按原文关键词判定，展示文本在桌面端
  映射为当前语言；新增 guardrail 需要同步映射表和语言包。
