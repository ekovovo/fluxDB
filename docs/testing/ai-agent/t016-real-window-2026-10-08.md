## 真实窗口验收

### 1. 主窗口可响应 — PASS

发送消息触发 burst 流,在流式期间立即点击主窗口搜索框区域(`wclick rel=130,116`)。
主窗口立即响应:AI 面板收起、主区域切换,无冻结或阻塞。截图 `t016-responsive.jpg`。

### 2. 取消事件不被大文本挤掉 — 自动化已覆盖,真实窗口未闭环

burst 夹具在一次 actor 线程循环内发射约 2100 个 `TextDelta`,真实窗口实测单次 Turn
从发送到 `completed` 只有约 130-140ms,远短于一次 CGEvent 点击的往返时延(200-500ms),
因此无法在真实窗口里把点击落在 140ms 窗口内。

该验收由两层自动化等价覆盖:

- `ai_runtime_cancel_before_submission_is_consumed_by_matching_turn_only`(运行时控制位语义)
- `ai_panel_scripted_stop_sets_cancel_flag_persists_interrupted_and_does_not_restart`
  (GPUI 面板实际点击停止 → 取消标志 → interrupted 落库 → 不重启)

### 3. 关闭窗口任务安全结束 — PASS

发送消息并让 burst 完成后,`kill -TERM <pid>` 优雅关闭应用:

- 进程在 3 秒内退出(`pgrep -x fluxdb-desktop` 无结果)。
- `PRAGMA integrity_check` = `ok`。
- 10 条 Turn 记录 `status=completed`,无脏写。

设计文档中记录的"显式 `shutdown(timeout)` 超时保留句柄"由
`ai_runtime_shutdown_timeout_keeps_join_until_external_call_returns` 覆盖。

### 4. 错误可见 — PASS

重启实例时切换 `FLUXDB_AI_E2E_STREAM=error`,发送消息后:

- SQLite: `ai_turns.status='failed'`,`error_code='离线流式错误夹具'`。
- UI: 抽屉底部出现红色错误卡片 "离线流式错误夹具",上方保留已流出的部分文本
  (`SELECT 1;`),下方显示 "重新加载会话" 按钮。用户消息 "err" 保留。截图 `t016-error-visible.jpg`。

## 未验证范围

- 真实模型付费调用不在本轮范围。
- 大文本流中"真实窗口手动点击停止"未闭环,由自动化等价覆盖。

## 结论

T016 四项验收中,三项(主窗口可响应、关窗安全结束、错误可见)在真实窗口拿到直接证据;

保留本记录作为差异说明。
