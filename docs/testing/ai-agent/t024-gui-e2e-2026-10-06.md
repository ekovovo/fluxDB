# D：真实窗口 GUI 端到端（Zhipu GLM + 真实 PostgreSQL，2026-10-06，macOS / podman）

## 环境与隔离

- 配置库：复制到 `/private/tmp/fluxdb-gui-e2e` 后启动（`FLUXDB_AI_TEST_ROOT`），**用户原始配置库不改**。
- 模型：`Zhipu GLM`（`openai-responses`）；数据库：用户 podman 的 `libredesk_db`（`127.0.0.1:5432`，连接 id=1）。
- 测试数据只写专用 schema `fluxdb_ai_smoke`，结束后 `DROP SCHEMA ... CASCADE`（已复核 `pg_namespace` 计数为 0）。
- 凭据走宿主解密路径，未外显。

## 为可复现性加的 debug 钩子

GUI 的 AI 目标平时来自"当前标签页"，E2E 里不稳定。新增 **仅 debug 构建**读取的
`FLUXDB_DEBUG_AI_TARGET='{"connection_id":1,"schema":"fluxdb_ai_smoke","object":"orders"}'`
（`main_parts/ai/actions.rs::ai_debug_target_override`）；生产构建不读该变量，永远用真实界面捕获。
另加 `examples/ai_gui_e2e_fixture.rs` 准备夹具（建 PG schema/表/2 行 + 在隔离副本里创建绑定 Zhipu 的 Agent）。

## 实机步骤与结果（全程真实点击/AX，非静态审查）

| 步骤 | 操作 | 结果 |
|---|---|---|
| ① 读回合 | 面板输入"用工具查询 fluxdb_ai_smoke.orders 两行并总结" → 真实点击**发送** | 模型调用 `db.query` → 真实 PG 回执 `rows=[["1","pending"],["2","paid"]]`；UI 出现「工具调用 已保存」「结果引用 已保存」两卡，AI 回答准确复述两行 |
| ② 写回合 | 输入"用 db.execute 把 id=1 改成 'paid'，用内联字面量" → 点击**发送** | `ai_turns.status=waiting_approval`、`ai_tool_calls(db.execute)=waiting_approval` **无回执**、`ai_approvals=pending`；UI 渲染审批卡（「批准执行 / 拒绝」+ "批准后仍会复核 plan_hash"） |
| ③ 批准 | 真实点击**批准执行** | 审批 `invalidated/consumed`；`db.execute=succeeded`，回执 **`affected_rows=1`**；Turn `completed` |
| ④ 后端核对 | podman psql 只读查询 | `fluxdb_ai_smoke.orders` = **`1|paid`、`2|paid`**（写入真实生效） |
