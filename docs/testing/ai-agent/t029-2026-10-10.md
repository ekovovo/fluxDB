# T029 停止、重启与未知副作用恢复（2026-10-10，macOS arm64）——通过

本轮补齐 `t029-restart-2026-10-06.md` 遗留的真实窗口 E2E：真实 PostgreSQL 写操作、
真实桌面窗口点击，并由数据库触发器提供副作用次数的独立事实。

## 隔离

- 配置副本：`/private/tmp/fluxdb-t029-root`（`FLUXDB_AI_TEST_ROOT`），不改用户原始配置库。
- 实例标识：`FLUXDB_PROFILE=t029-e2e`，与日常实例的单实例锁隔离。

  `127.0.0.1:55433`，只含专用schema `t029`，无业务数据。
- 凭据只在宿主进程内解密后交给 connector，未打印、未写入日志或证据。

### 副作用事实来源

```sql
CREATE TABLE t029.orders (id int primary key, status text not null, amount numeric(10,2) not null);
CREATE TABLE t029.write_count (id int primary key, cnt int not null);
CREATE TRIGGER orders_bump AFTER UPDATE ON t029.orders
  FOR EACH ROW EXECUTE FUNCTION t029.bump();  -- 每成功 UPDATE 一次 cnt+1
```

`t029.write_count` 是唯一副作用计数来源，不用工具卡文案或本地事实行数代替。

## 逐步骤与后端断言

### ① 未知写：UI 可见且不自动重放

截图 `evidence/t029-unknown.jpg`：工具卡显示红色「**结果未知**」，告警条
「应用已重启：有工具调用未收到执行回执，实际结果未知。不会自动重放；请先核对数据库/外部系统，未核实前禁止重复写入。」，
无任何重试入口。

后端：`ai_tool_calls.status='unknown'` 且 `receipt_json` 为空；`status='unknown' AND receipt_json IS NOT NULL` 计数为 **0**（未伪造回执）。

### ② 同连接未知副作用 → 拒绝冲突写入

在仍有 unknown 的连接 8 上批准新的 `db.execute`：

截图 `evidence/t029-conflict.jpg`：批准后仍被拒，「本轮未能开始：目标存在尚未核实的未知执行结果，拒绝冲突写入」。

后端：`t029.write_count.cnt = 0`，`t029.orders` 两行均为 `pending`；该调用停留在
`waiting_approval`，从未执行。**一次副作用都未发生。**

### ③ 重启后重新审批 → 真实写入恰好一次

在干净连接 9 的 `t029-approval-*` 会话点击「批准一次」
（截图 `evidence/t029-reapproval.jpg` 为重启后的待审批卡）。

后端：

| 检查 | 结果 |
| --- | --- |
| `t029.write_count.cnt` | 0 → **1** |
| `t029.orders` id=1 | `pending` → `paid` |
| 工具卡 | `succeeded`，真实回执`elapsed_ms=63` |
| 审批 | `invalidated` / `consumed`（不可重用） |
| 针对 `id=1` 的写调用条数 | 2 条，但连接 8 那条从未执行（`waiting_approval`），仅连接 9 那条 `succeeded` |

### ④ 重启后不重放

再次启动桌面端（触发第二轮扫描）后复核：

| 检查 | 结果 |
| --- | --- |
| `t029.write_count.cnt` | 仍为 **1** |
| `t029.orders` id=1 | 仍为 `paid` |
| 已 `succeeded` 的调用 | 未被改写 |

### ⑤ 正文、草稿与锚点

- 读中断会话的部分回复「已保存的部分回复：重启后这段内容不能丢失。」在扫描后仍存在，
  工具卡状态为「已停止」而非「完成」。
- `ai_session_ui_state.draft_json` 在两个中断会话中均为
  `{"text":"恢复后保留这份未发送草稿"}`，草稿与滚动锚点保留。

## 结论与范围

T029 列出的E11 四步（长读停止→等待审批重启→中断写 unknown→禁止重放）已用真实窗口、
真实 PostgreSQL 与触发器计数完成验证，「副作用调用计数证明没有重复执行」成立。

范围与未验证项：

- 停止（`CancelAiTurn`）路径本轮由存储/GPUI 回归覆盖（`ai_recovery`、
  `tests_recovery.rs`），真实窗口的长读停止未单独掐进程复现；
  读中断的 `running → cancelled` 事实由真实启动扫描产生。
- 跨系统提交核实/幂等键、远端状态探测、人工核实记录仍属设计 §11.1 声明的后续能力，
  本轮维持既有边界：只保证可见警告、禁止自动重放与同连接冲突拒绝。
- 仅macOS；Windows / Linux 未验证。
- 未连接用户真实业务库，未执行 `FLUSHALL` 或重置容器；清理限于本run 的 `t029` schema。
