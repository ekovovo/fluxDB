# ③ 真实模型 + 真实 PostgreSQL 端到端验收（2026-10-06，macOS / podman）

## 环境

- 数据库：用户 podman 起的 `libredesk_db`（`postgres:17-alpine`，`127.0.0.1:5432`，连接 id=1 `libredesk`）。
  MySQL（36531）当时未启动，Redis（6379）已启动但 Redis 工具尚未实现，故本轮只验 PostgreSQL。
- 模型：`Zhipu GLM`（`openai-responses`，本轮新实现并已验证；`公司自建` 整站 403 不可达）。
- 隔离：把用户配置库复制到 `/private/tmp/fluxdb-live-e2e` 后使用，**用户原始配置库零改动**；
  测试数据只写在专用 schema `fluxdb_ai_smoke`，结束即 `DROP SCHEMA ... CASCADE`。
- 凭据：走宿主自身路径（`load_connections` 内部解密注入），只在进程内存在，未打印任何密钥。

## 执行方式

新增 `crates/fluxdb-app/examples/ai_live_pg_e2e.rs`（需 `FLUXDB_AI_LIVE=1` + 隔离 root 显式启用）：

```text
FLUXDB_AI_LIVE=1 FLUXDB_AI_LIVE_ROOT=/private/tmp/fluxdb-live-e2e \
FLUXDB_AI_LIVE_MODEL='Zhipu GLM' FLUXDB_AI_LIVE_PG_CONNECTION=1 \
cargo run -p fluxdb-app --example ai_live_pg_e2e
```

它走的是生产链路：`AppController::prepare_ai_conversation` → `run_ai_conversation_turn`
（真实 Provider + 真实 `standard_sql_catalog`，含写工具）→ `DecideApproval` → `prepare_ai_resume_job` →
`run_ai_conversation_resume_approval`。

## 结果

| 步骤 | 实际 | 结论 |
|---|---|---|
| 建 fixture | `CREATE SCHEMA fluxdb_ai_smoke` + `orders(id,status,amount)` + 2 行；写入前 `["1|pending","2|paid"]` | ✅ |
| ① 真实模型读 | `db.query` → `status=succeeded`，真实回执 `columns=["id","status"], row_count=2, rows=[["1","pending"],["2","paid"]]`；模型回答准确复述 2 行 | ✅ |
| ② 真实模型写 | `db.execute` → **停在审批**，`receipt_json` 为空；审批前数据核对仍为 `["1|pending","2|paid"]`（未执行） | ✅ |
| ③ 批准 + 恢复 | 审批 CAS 通过 → 恢复执行：`db.execute` → `status=succeeded`，回执 `affected_rows=1, statement_kind=command` | ✅ |
| ④ 后端核对 | 真实查询：`["1|paid","2|paid"]`（写入生效） | ✅ |
| ⑤ 模型自我核验 | 模型在写入后**自己又发起一次 `db.query`** 核验，并回答"回执 affected_rows=1 与当前值一致，更新已生效" | ✅ |
| ⑥ 清理 | `DROP SCHEMA fluxdb_ai_smoke CASCADE` | ✅ |

即 ③ 的 PostgreSQL 部分达成：**真实模型 → 固定目标连接 → 只读/写工具 → 审批闸门 → 真实执行 → 真实 affected_rows → 后端前后值核对 → 模型自我验证**。

## 本轮发现的产品缺口（未在本轮修）

- **参数化执行尚未支持**：模型第一次写请求带了 `parameters`，被 `db.execute` 按设计拒绝
  （`parameters_unsupported`：连接器没有 bind，宁可拒绝也不做字符串拼接）。
  模型随后自行判断"改用内联值重试"，但这一轮以说明性文本结束。
  端到端验收因此显式要求模型"使用内联字面量"——**这是产品现状，不是测试作弊**。
  ⇒ 真实模型天然倾向用参数占位符，`ParameterizedQueryRequest` + 驱动 bind（sqlx/rust-postgres）应优先补齐。
- 模型在最终回答里保留了"需要审批后才能执行"的说明，这是好的透明度；但审批前后同一 Turn 的文案衔接还可优化。
