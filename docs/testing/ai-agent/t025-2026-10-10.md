# T025 Redis 工具实施与验收记录（2026-10-10）

平台：macOS arm64。基线：fc45541。GPUI 依赖未升级。

## 变更

- 审批恢复后的工具调用不再复用归零的内存序号；在 IMMEDIATE 事务中分配持久化序号并写入事实行、审批与卡片，修复 UNIQUE(turn_id, iteration, source_ordinal) 冲突。
- SCAN 有轮数、时间与 Key 数量边界、客户端去重和范围说明。COUNT 超额批次明确报错，不能截掉剩余 Key 后假称扫描完成。
- inspect 按实际类型选择有界读取；string/list 支持 offset、集合支持 cursor、stream 支持 entry ID 续读。读取错误向上传播，模块类型只返回元数据说明。
- AI Redis 命令使用 RESP 解码预算，累计限制 bulk、总字节、元素数与深度；未消费的超限帧令连接损坏，不回连接池。普通桌面路径保留大值预算。
- 默认拒绝 Lua/function、KEYS 与管理/阻塞入口，MEMORY 校验子命令。Cluster 拒绝非 DB 0；扫描明确为连接节点范围。
- 发送前取消不执行；发送后的取消竞态报告 unknown，不宣称撤销副作用。
- AI 输入框和发送按钮提供稳定无障碍标识；移除了本任务中尝试添加的自动提交钩子。

## 补充：命令 Key spec 与授权范围校验（2026-10-10 续）

平台：macOS arm64，Redis 7.2.7（隔离实例，端口 6397，验证后已 shutdown 并清理）。

### 改动

- 新增 `ai_redis_keys.rs`：按命令 key spec 解析 argv 中的全部 key（`RedisKeyExtraction`），
  区分单 key / 多 key / 成对 key / 无 key / **不可解析**。
- 不可解析一律 fail closed：脚本（EVAL/FCALL/FUNCTION/SCRIPT）、跨节点 MIGRATE、
  跨库 MOVE、模块与未知命令返回 `Unresolvable` 并在发送前拒绝（`redis_key_scope_unresolvable`）。
- `RedisKeyScope` 为显式类型（`AllKeys` / `Prefixes`），**空 prefix 不等于全 Key**（§28.6.1）；
  刻意不实现 `Default`，避免未配置的空规则被当成全库通行。
- `SqlExecutionResolver::redis_key_scope` 为授权接入点：默认按用户显式选中的连接放行全 Key
  （引入 prefix 前的既有行为，写命令仍逐次审批）；T057 的 profile 授权落地后由实现方返回
  `Prefixes` 收紧，范围不接受模型自带的声明。
- `redis.execute` 在发送前校验全部 key（含源与目标），回执新增 `scope_info`（DB、实际触碰的
  key 与数量）便于审计核对；`redis.inspect` 校验目标 key；`redis.scan` 用授权 prefix 过滤
  结果——**pattern 是检索条件，不是授权**。

## 手动验收：Prefix 授权路径（2026-10-10 续）

平台：macOS arm64，真实桌面窗口 + 用户现有 Redis 7.4.11 连接（`conn:3/db:0`）。

为让用户在真实 UI 测试 prefix 授权，本轮补了两处入口：

- `MapSqlResolver::redis_key_scope` 默认实现读取连接 `options["ai_key_prefixes"]`
  （逗号分隔，空/全逗号视同未配置），未配置仍为既有 `AllKeys` 行为。
- 桌面连接表单「连接参数」白名单加入 `ai_key_prefixes`，占位符与说明同步；
  设置页工具目录补上 `redis.subscribe` 并新增一致性测试
  （目录必须覆盖实际注册的 Redis 工具）。

用户在真实窗口按步骤手动验收**全部通过**：

1. 默认（未配置 prefix）：`SET` 成功，回执 `scope_info` 含 DB、key 与数量。
2. 配置 prefix 后读越界 key：`redis.inspect` 返回失败，错误码 `scope_mismatch`，
   文案含「不在授权的 prefix 范围内」；模型由此自知范围并改走授权内路径。
3. 配置 prefix 后读授权内 key：inspect 成功。
4. 配置 prefix 后写越界 key：审批确认后被 `scope_mismatch` 拦截，服务端无写入。
5. 配置 prefix 后写授权内 key：成功且 `scope_info` 按审计口径回填。
6. 多 key 命令（MSET）任一 key 越权：整体拒绝，授权内 key 也未写入。
7. `redis.scan` 宽 pattern：结果不泄漏越界 key。
8. 不可解析命令（如 `BF.ADD`）：被拒（`redis_key_scope_unresolvable`）。
9. 订阅上限：`redis.subscribe` 按 `max_messages` 提前收工（`message_limit`）。

用户确认「全部测试完成」后，T025 按 Cluster 例外勾选（见 §T025 补记）。

## 补充：有界订阅（2026-10-10 续）

基线：9ac5c9b。平台：macOS arm64，Redis 7.2.7（`redis-server` 本机隔离实例，端口 6397，验证后已 shutdown 并清理）。

### 改动

- 新增 `redis.subscribe` 工具（ToolRisk::Read）：入参 `target` / `channels` / `pattern` / `max_messages` / `max_bytes` / `timeout_ms`。
- `redis.execute` 仍拒绝 `SUBSCRIBE`/`PSUBSCRIBE`/`SSUBSCRIBE`，拒绝原因为 `use_redis_subscribe_tool:*`：一次性 argv 执行会把连接挂成长会话，订阅必须走专用有界工具。
- 连接器新增 `RedisConnector::collect_subscription`：专用连接（不入池），发订阅后循环读 push 消息，命中条数 / 字节 / 时限任一上限或取消即退订断开；收工原因区分 `message_limit` / `byte_limit` / `time_limit` / `canceled`。
- 交互式 `RedisPubSubSession` 与一次性收集共用 `redis_classify_pubsub_value`，避免两条路径对同一 push 回包理解不一致。
- 取消语义与 SQL 一致：只声明客户端停止接收，返回 `cancel_race_unknown`（receipt `Unknown`），不宣称服务端已撤销已投递消息。
- 载荷二进制时按 `payload_bytes` + `bytes_preview_hex` 投影，不做 lossy UTF-8 强转。
