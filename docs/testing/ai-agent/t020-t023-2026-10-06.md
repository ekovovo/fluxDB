# T020/T023 进展记录（2026-10-06，macOS）——**未完成，不勾选**

## 范围与版本

- 分支 `agent`；设计入口：`docs/ai-agent-design.md` §20（工具协议）、§21（查询/只读保证）、§25（审批）、§31（面板）。
- 本轮把"工具真实回执"接进会话持久化与桌面发送链路：**只读工具可用**，写工具仍不注册。

## 改动要点

**storage**
- `conversation::upsert_event_part(...)`：把工具卡/结果卡/通知片段挂到 assistant message；带 Turn 归属校验与终态拒绝（迟到事件不落库）。
- `sessions::start_tool_call(...)` / `finish_tool_call(...)` / `insert_result(...)`：写 `ai_tool_calls` / `ai_results` 事实行。片段表对它们有外键
  （`tool_call_ref`/`tool_result_ref` 必须带 `tool_call_id`），所以必须"先事实行、后片段"，不能只塞 JSON。

**app**
- `AiConversationProvider`：把既有 transport 包成 `GenerationProvider`（含工具声明与 `anthropic-version`）；
  凭据在构造时 AES 解密后只交给 transport，结构体不实现 `Debug`、不进日志/事件/持久化。
- `run_ai_conversation_turn(...)`：用 `TurnRunner` 跑完整链路（schema → 审计 → 授权 → 执行 → 有界投影），
  把文本/摘要走原 checkpoint 路径，把工具卡、结果卡、通知写成片段；`Paused` 映射为 `waiting_approval`。
- 参数脱敏：`ai_tool_calls.arguments_redacted_json` 保留 `sql`/`target`，剔除 `password`/`secret`/`token`/`api_key`/`credential` 等字段。
- `run_ai_conversation_failure(...)`：无法启动时写可见错误并把 Turn 置为 `failed`（不静默、不伪造成功）。
- `KernelAuditHook`：内置规则审计（当前只有内核风险/白名单/连接权限，由 `authorize` 强制执行）。

**desktop**
- 正式发送不再走"只解释不执行"的单轮路径：改为构造只读 `standard_sql_catalog(resolver, false)`（`db.search_objects`/`db.query`/`db.explain`）
  + `KernelPolicy::default()`（可读不可写），调用 `run_ai_conversation_turn`。写工具**不注册**，因此不会被执行。
- 连接配置从当前 AppState 克隆进后台线程（配置不含凭据）。

### 子 Agent A 独立测试（`crates/fluxdb-app/tests/ai_conversation_tools_guard.rs`，6 例）

| # | 场景 | 预期 | 结果 |
|---|---|---|---|
| 1 | 工具卡与事实行闭环 | `ai_tool_calls.status='succeeded'`、`receipt_json`/`plan_hash` 非空；`ai_results.source_call_id` 指向它；两类片段外键正确；重开存储仍成立 | 通过 |
| 2 | 参数脱敏 | 嵌套 `parameters` 里的 `password`/`api_key`/`token` 字段与值都不得进 `arguments_redacted_json` | **首轮失败（P1）**，修复后通过 |
| 3 | 迟到/终态拒绝 | 终态 Turn 或归属不符时 `upsert_event_part` 返回 Err 且不新增片段行 | 通过 |
| 4 | 未知工具 | `db.execute` 不在只读目录 → 无 `ai_tool_calls`/`ai_results`/结果卡，但有 `notice`（外键为 NULL） | 通过 |
| 5 | 纯文本回合 | 文本入库、Turn `completed`、工具事实行 0 | 通过 |
| 6 | 失败可见 | `run_ai_conversation_failure` 写可见错误、Turn `failed`、工具事实行 0 | 通过 |

**修复的 P1（子 Agent 发现）**：`ai_conversation_redact_arguments` 原先只过滤顶层键，嵌套对象/数组里的
`password`/`api_key`/`token` 会被原样写入 `ai_tool_calls.arguments_redacted_json`。
已改为递归脱敏（对象键 + 数组元素），复跑该文件 6/6 通过。

### 主 Agent 集成测试 `crates/fluxdb-app/tests/ai_conversation_tools.rs`（2 例）
- 只读回合：记录工具调用卡与结果卡 → 重开 `FileStorage` 仍存在，`db.query` 回执 `succeeded`，Turn `completed`，审计确实被调用；

- **审批未落盘**：`ai_approvals` 的 create/decide/按 plan_hash 复核还没接；暂停的 Turn 目前没有恢复入口（`AiEvent::Paused` / `TurnStatus::WaitingApproval` 已就位）。
