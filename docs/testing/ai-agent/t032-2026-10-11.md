## A. 自动化验收（复制粘贴即可，不需要看代码）

每一步都：粘贴命令 → 回车 → 等结束 → 对照「期望」。

### A1 内置能力注册表

```sh
cargo test -p fluxdb-app --test ai_builtin_registry --locked --offline
```

期望：`test result: ok. 3 passed`。
覆盖：12 项内置能力齐全、与 storage 注册表一致、强制实例不可停用、未知/禁用/外部 runtime 不进能力集合。

### A2 Hook 顺序、冲突、禁用、递归、超时、失败策略

```sh
cargo test -p fluxdb-app --test ai_hook_pipeline --locked --offline
```

期望：`test result: ok. 7 passed`。
覆盖：priority 稳定排序；同字段冲突 fail closed；`Deny` 优先；after-tool 不能改写真实回执；禁用/取消零调用；递归被拒；超过 100ms 时限被拒；`best_effort` 失败降级而非中断。

### A3 before-tool 补丁必须重新校验并重放一致

```sh
cargo test -p fluxdb-app --lib --locked --offline ai_loop 2>&1 | tail -25
```

期望：`test result: ok. 21 passed`。其中三条是本任务新增：
`ai_loop_hook_patch_cannot_change_execution_target`、`ai_loop_hook_patch_is_revalidated_before_execution`、`ai_loop_hook_patch_is_applied_and_replayed_in_assistant_tool_call`。
覆盖：改目标直接失败且工具零执行；补丁使参数不合 schema 时不执行工具并把结构化错误回给模型；合法补丁后工具收到最终参数，assistant 的 tool_call 回写同一参数。

### A4 `#plugins` 页面结构（无头 UI 测试）

## B. 真机窗口验收

### B1 用隔离目录启动

```sh
rm -rf /tmp/fluxdb-t032-e2e && mkdir -p /tmp/fluxdb-t032-e2e
FLUXDB_AI_TEST_ROOT=/tmp/fluxdb-t032-e2e \
FLUXDB_DEBUG_AI_SETTINGS=tools FLUXDB_DEBUG_AI_TAB=plugins \
cargo run -p fluxdb-desktop
```

说明：`FLUXDB_AI_TEST_ROOT` 把全部数据落到临时目录；两个 `FLUXDB_DEBUG_*` 让窗口直接停在「设置 → 工具与 MCP → 内置插件」。

### B2 逐项核对页面

1. 顶部标题是「工具与 MCP」，四个页签「工具 / 本地 MCP / 内置插件 / 安全审计」中「内置插件」高亮。
2. 能力框标题为「内置能力」，右侧小字是「12 项 · 第三方仅预留接口」。
3. 列表共 12 行，**顺序与原型一致**（按设计 §23.2 目录顺序，不是按名称排序）：当前界面与 @ 上下文、数据库与 Redis 工具、文件与附件、模型路由、Jev 决策优化、上下文压缩、调用前安全审计、Token 用量与执行保护、业务知识与 Skills、BI 与报表输出、计划与执行进度、生命周期诊断。
4. 每行三行信息：名称（粗体）、说明（灰色小字）、`fluxdb.xxx · 内置`；每行左侧有图标，右侧有开关。
5. 强制项「调用前安全审计」「Token 用量与执行保护」显示蓝色「内核约束」标签，开关为灰掉不可点。
6. 其余行显示「已启用」绿色标签。
7. 页面底部有一条提示：「第三方插件安装、市场与沙箱当前不实现。未来通过相同的能力契约扩展，不直接访问数据库、密钥或界面控件。」

### B3 真实启停并复核落库

1. 点击「生命周期诊断」行的开关（窗口小的话先往下滚动）→ 该行标签变为「已关闭」。
2. 点击「调用前安全审计」行的开关（灰掉）→ 标签仍是「内核约束」，开关不动。
3. 关掉应用窗口，重新执行 B1 的启动命令 → 「生命周期诊断」仍是「已关闭」（说明真实落库，不是只在内存里改）。
4. 复核数据库（可选，另开一个终端）：

```sh
sqlite3 -header -column /tmp/fluxdb-t032-e2e/fluxdb.sqlite \
  "select i.id, p.package_key, i.enabled from ai_plugin_instances i join ai_plugin_packages p on p.id=i.package_id order by i.id;"
```

期望：12 行；`builtin.telemetry` 的 enabled 是 0；`builtin.security-audit`、`builtin.budget` 的 enabled 是 1。
